# 系统架构

本文件描述系统分层和技术边界。若要了解仓库里每个目录与文件的作用、启动链路和修改入口，请先阅读 [仓库导航与代码地图](repository-guide.md)。

## 1. 总体结构

```text
┌──────────────────────────────────────────────┐
│ React + TypeScript                          │
│ 窗口、工具栏、缩略图、可见页面调度、错误展示 │
├──────────────────────────────────────────────┤
│ PDF.js                                      │
│ PDF 解析、页面渲染、文本和页面元数据         │
├──────────────────────────────────────────────┤
│ Tauri 命令边界                              │
│ 只暴露经过允许的本地能力                    │
├──────────────────────────────────────────────┤
│ Rust                                        │
│ 文件选择、只读访问、任务生命周期、错误归类   │
├──────────────────────────────────────────────┤
│ Windows 文件系统 / WebView2                 │
└──────────────────────────────────────────────┘
```

第一版不引入 qpdf 和 Tesseract。它们分别在页面写入和 OCR 阶段再加入，避免预览器阶段承担不必要的依赖与风险。

## 2. 为什么使用这套结构

### React + TypeScript

负责交互状态和界面组合。PDF 查看器会有大量异步状态，例如当前文件、当前页面、缩放比例、正在渲染的页面以及已经取消的任务；显式的数据模型比直接操作界面元素更容易测试。

### PDF.js

负责理解和显示 PDF。第一版不自己实现 PDF 语法、字体、图像解码或页面绘制。

### Rust

负责安全边界而不是 PDF 渲染：

- 检查和规范化用户选择的路径；
- 以只读方式打开文件；
- 限制前端可以访问的文件；
- 为后续文件写入提供可靠的错误处理；
- 管理可取消的后台任务。

### Tauri

负责桌面窗口和前后端通信。前端不能接收任意命令并将其拼接成系统命令；每一种能力都必须对应一个参数类型明确的 Rust 命令。

## 3. 第一版的数据流

```text
用户选择文件
    ↓
Rust 验证路径、类型、大小和可读性
    ↓
为本次打开操作创建文档会话
    ↓
PDF.js 按需读取并解析文档
    ↓
界面只请求当前视口附近页面
    ↓
渲染任务完成、取消或报告结构化错误
    ↓
关闭文档时释放 Worker、画布、缓存和文件句柄
```

具体采用一次性字节传输、受控本地协议还是分段读取，需要在架构验证阶段用大文件测量后决定。

## 4. 关键模块边界

### DocumentSession

每个打开的 PDF 对应一个会话，至少包含：

- 不向界面暴露的内部文档标识；
- 显示名称；
- 文件大小；
- 页数；
- 加载状态；
- PDF.js 文档实例；
- 可取消任务集合；
- 页面缓存预算。

关闭会话必须释放上述资源。

### RenderScheduler

负责：

- 优先渲染当前可见页面；
- 少量预取相邻页面；
- 取消远离视口的任务；
- 限制同时渲染数量；
- 控制画布和位图缓存总量。

### ErrorModel

底层错误不得直接显示给用户。统一映射为：

- FileNotFound；
- PermissionDenied；
- PasswordRequired；
- InvalidOrDamagedPdf；
- UnsupportedFeature；
- OutOfMemoryRisk；
- Cancelled；
- Unexpected。

开发日志可包含技术原因，界面显示可理解的中文说明。

## 5. 状态管理原则

- 文档事实只有一个来源；
- 页面渲染结果属于缓存，不属于永久状态；
- 用户切换文档后，旧任务即使返回也不能更新新文档界面；
- 使用会话编号防止异步结果串台；
- 所有长期监听器和 Worker 都必须有明确销毁路径。

## 6. 后续写入架构

页面编辑阶段将维护“操作计划”，而不是每次操作立即重写 PDF：

```text
输入文档（只读） + 页面操作计划 → 临时输出 → 验证 → 用户目标文件
```

未来任何写入实现必须遵守 `safety.md`，并且不得绕过临时文件和验证步骤。

## 7. 尚待验证的架构问题

1. Tauri 中向 PDF.js 提供本地文件的最佳方式；
2. 大 PDF 一次性传输与分段读取的内存差异；
3. PDF.js Worker 在 WebView2 中的打包和 CSP 配置；
4. 高 DPI、缩放和快速滚动时的缓存预算；
5. 密码保护 PDF 的交互方式；
6. 应用关闭或切换文件时，所有任务是否可靠取消。

这些问题通过最小技术实验解决，不依赖猜测。
