# 文件与系统安全规则

本文是文件、系统能力、资源和隐私规则的唯一权威来源。这些是强制约束，不是建议。系统边界见[架构](architecture.md)，验证方式见[测试策略](testing.md)；产品文档只保留安全目标，不重复这里的实现规则。

## 1. 第一版的只读保证

- 第一版不提供任何保存或修改命令；
- 输入 PDF 只以读取方式打开；
- 不更新文件元数据；
- 不在输入文件同一路径创建同名临时文件；
- 不因为“修复损坏 PDF”而静默改写原件；
- 预览失败只报告错误，不尝试自动覆盖修复。

## 2. 路径处理

- 不使用字符串拼接构造路径；
- 不将文件名插入 shell 命令；
- 不允许前端提交任意路径后直接读取；
- 只访问用户明确选择的文件；
- 支持 Unicode 和长路径；
- 正确处理符号链接、快捷方式、网络盘和只读介质；
- 日志默认使用显示名称，不记录完整路径；调试模式例外需明确标识。

## 3. 不可信 PDF

所有 PDF 都视为不可信输入，包括来自论文网站、邮件和扫描仪的文件。

- 禁止执行 PDF 内嵌 JavaScript；
- 禁止自动打开附件和外部链接；
- 禁止 PDF 自动发起网络请求；
- 不信任 PDF 声明的页数、尺寸和对象长度；
- 对异常大页面和内存请求设置上限；
- 解析和渲染错误不能升级为任意系统能力；
- PDF.js 和相关解析依赖需要跟踪安全更新。

## 4. 资源保护

- 限制并发渲染页数；
- 限制画布最大边长和像素总量；
- 缓存必须有明确的内存预算和淘汰策略；
- 用户切换文件后取消旧任务；
- 关闭窗口时终止 Worker 和后台任务；
- 遇到资源不足时降级或停止，不让系统进入换页风暴。

## 5. 后续版本的写入协议

当项目加入保存、合并或拆分后，所有输出必须遵循：

1. 输入文件保持只读；
2. 在目标目录或安全临时目录生成唯一临时文件；
3. 写入完成后刷新并关闭文件句柄；
4. 重新打开临时文件，验证 PDF 头、尾、页数及基本可读性；
5. 检查剩余磁盘空间和目标冲突；
6. 仅在验证成功后提交到用户指定的新路径；
7. 若目标已存在，必须再次得到用户明确确认；
8. 提交失败时保留原目标，不做半覆盖；
9. 清理本次操作创建的临时文件；
10. 不提供默认“覆盖原文件”按钮。

是否采用原子重命名取决于临时文件与目标是否位于同一文件系统；跨卷操作不能假设原子性。

## 6. 外部程序规则

后续调用 qpdf、Tesseract 等程序时：

- 使用参数数组，不经 shell 拼接；
- 可执行文件路径固定且经过校验；
- 设置超时、取消和输出大小限制；
- 不信任标准输出和错误输出；
- 固定并记录版本和校验值；
- 打包其许可证和必要声明；
- 子进程结束后确认无残留任务。

## 7. 隐私

- 默认不联网；
- 不收集遥测；
- 不上传崩溃文件或 PDF 内容；
- 最近文件列表属于可选本地数据，必须可以关闭和清空；
- 日志不得包含页面正文、OCR 内容、密码和批注内容；
- 如果未来检查更新，更新功能与文档处理数据必须完全隔离。

## 8. 安全验收

第一版发布前至少验证：

- 打开并关闭文件后 SHA-256 不变；
- 文件修改时间不变；
- 只读文件和只读目录可正常预览；
- 无权限文件得到 PermissionDenied；
- 损坏文件不崩溃；
- 超大页面不会分配无限画布；
- 嵌入脚本、附件、链接不会被自动执行；
- 快速反复打开文件不会产生句柄泄漏；
- 应用退出后不存在遗留后台进程。
