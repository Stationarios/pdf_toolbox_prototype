# 测试策略与真实样本清单

## 1. 测试集目录约定

将来测试文件建议放在：

```text
tests/fixtures/
├─ public/        可以随仓库公开的小型样本
├─ generated/     由我们生成、可重复生成的样本
└─ private/       真实论文和私人文件，不提交 Git
```

`private/` 必须加入 `.gitignore`。含个人信息、未公开论文、付费数据库内容和版权不明文件只能留在本地。

## 2. 样本登记表

每个样本使用一个不泄露正文的记录：

```text
编号：PDF-001
公开性：public / generated / private
来源与授权：
文件大小：
页数：
主要特征：
预期结果：成功 / 需要密码 / 拒绝 / 可容错打开
已知阅读器表现：Edge / Firefox / Acrobat
是否允许提交仓库：是 / 否
备注：
```

私人样本登记时只写特征，不写论文题目、作者、正文或完整文件路径。

## 3. 优先准备的最小测试集

一开始不需要收集几十个文件。先准备以下八类：

1. 一页普通文本 PDF；
2. 十页左右、包含图片和文字的普通 PDF；
3. 中文文件名和中文正文；
4. 双栏论文；
5. 纯扫描图片 PDF；
6. 横向页面或混合纵横页面；
7. 受密码保护的 PDF；
8. 体积较大或页数很多的 PDF。

其中 1、3、6 可以由项目自行生成，避免版权问题。

## 4. 后续扩充类别

### 页面结构

- 空白页；
- 不同页面尺寸混合；
- CropBox 与 MediaBox 不同；
- 页面带 90/180/270 度旋转属性；
- 极大或极小页面；
- 透明度、渐变、复杂矢量图；
- 嵌入字体、缺失字体、CID 字体；
- 黑白、灰度、RGB、CMYK 图片。

### 文档功能

- 书签和目录；
- 内部链接和外部链接；
- 已有高亮和批注；
- 表单；
- 附件；
- 数字签名；
- PDF/A；
- 线性化 PDF；
- 增量更新过多次的 PDF。

### 异常输入

- 扩展名是 `.pdf` 但内容不是 PDF；
- 正常 PDF 使用其他扩展名；
- 文件被截断；
- 交叉引用表损坏；
- 0 字节文件；
- 无读取权限；
- 打开期间被移动或删除；
- 网络盘突然断开；
- 声明极端页尺寸或对象大小的恶意样本。

### 路径

- 中文；
- 空格；
- 括号和方括号；
- `#`、`&`、单引号；
- emoji；
- 很长的路径；
- 只读目录；
- U 盘或网络路径。

## 5. 测试层次

### 单元测试

不打开真实窗口，测试页码、缩放、错误映射、缓存策略和状态转换。

### 集成测试

验证 Rust、Tauri 和 PDF.js 的边界，例如打开文件、取消会话和资源释放。

### 视觉测试

对固定页面在固定缩放下截图，与基准图比较。允许少量抗锯齿差异，但不能漏字、错位或黑屏。

### 手工真实文件测试

使用 `private/` 中不能公开的论文和扫描文件，记录结果但不提交文件。

### 安全回归测试

每个版本检查输入文件哈希、修改时间、句柄释放和后台进程。

## 6. 每个样本的首版检查项

- 能否打开；
- 首屏出现时间；
- 页数是否正确；
- 第一页、中间页、最后一页是否正常；
- 缩放和滚动是否正常；
- 内存是否持续增长；
- 关闭后能否立即重命名或删除测试文件；
- 原文件哈希和修改时间是否保持不变；
- 错误是否符合预期。

## 7. 不要故意制造危险测试

第一阶段不要从不可信网站下载所谓“恶意 PDF 样本包”。安全测试样本应来自可信安全项目、由我们可控生成，或者在隔离环境中处理。普通开发机不承担恶意软件分析任务。
