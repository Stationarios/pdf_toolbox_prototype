# 文档中心

这里存放 PDF Toolbox 的产品、技术与验证文档。项目仍处于早期阶段，文档会随实现演进；本页负责告诉你**为了完成某件事应该读什么**，而不是要求从头读完所有文件。

## 第一次了解项目

建议依次阅读：

1. [产品范围](product.md) — 第一版阅读器为谁而做、必须实现什么、明确不做什么，以及完成标准。
2. [开发路线图](roadmap.md) — 项目目前位于哪个阶段，各阶段的交付物和退出条件。
3. [系统架构](architecture.md) — 当前原型如何运行、目标阅读器怎样分层，以及关键生命周期和技术约束。

## 准备修改代码

- [仓库与代码导航](repository-guide.md) — 目录和文件的职责、常用命令，以及修改某项功能应该从哪里开始。
- [测试策略](testing.md) — 测试层次、真实样本管理、边界情况和每个样本的检查项。
- [安全规则](safety.md) — 输入文件只读保证、资源限制、隐私规则及未来写入协议。

## 查找设计依据与历史结果

- [架构决策记录](decisions/README.md) — 已接受的重要产品和技术选择，以及它们当时的理由与代价。
- [验证记录](validation/README.md) — 已完成实验的环境、样本、观察结果和结论；它记录事实，不定义当前需求。

## 学习背景

- [给 C 使用者的 Rust/Tauri 心智模型](rust-for-c-programmers.md) — 只介绍参与本项目所需的 Rust 概念，不是完整教程。

## 文档职责速查

| 问题 | 唯一权威来源 |
| --- | --- |
| 第一版到底做什么？ | [产品范围](product.md) |

| 系统怎样分层、数据怎样流动？ | [系统架构](architecture.md) |

| 应该怎样验证一个功能？ | [测试策略](testing.md) |
| 为什么选择某项方案？ | [架构决策记录](decisions/README.md) |
| 某次实验实际发生了什么？ | [验证记录](validation/README.md) |

如果内容同时涉及多个主题，只在权威文档中完整解释；其他文档保留一句摘要并链接过去，避免多份说明逐渐互相矛盾。
